# 前景

本前景文档旨在收集、分析和定义“论文智能管理与知识库系统”的高层次需求和特性。通过明确涉众和目标用户的功能需求、非功能需求及约束条件，为后续的系统设计、开发和验收提供依据。

# 1. 简介

## 1.1 目的

本文档的目的是向项目团队、评审者及其他涉众清晰展示系统的愿景和范围。它通过描述系统目标、核心功能、质量特性及约束，指导团队聚焦于解决科研信息过载问题。

## 1.2 范围

该系统是一款面向科研人员、学生和图书馆员的 Web 应用，提供以下主要能力：

- 自动从 arXiv 拉取指定学科或关键词范围内的论文，实现分类入库及去重。
- 解析论文 PDF/HTML 内容，生成结构化摘要、概念和方法文档，抽取核心概念及研究结论。
- 构建论文知识 Wiki，支持多维检索并展示引用关系、主题关联与概念关联。
- 提供基于向量搜索和大型语言模型的智能问答服务，回答用户对论文内容、概念解释和研究脉络的提问。
- 支持收藏、笔记、评论和对比阅读等学习管理功能，并记录用户阅读历史和关注主题。
- 进阶功能包括研究脉络分析与个性化推荐。

## 1.3 定义、首字母缩写词和缩略语

| 缩写/术语 | 定义 |

# 2. 定位

## 2.1 商机

随着数字化知识的爆炸式增长，信息过载已成为科研群体的普遍困扰。数据统计显示，全球每天产生约 403 万 TB 的数据，80% 的知识工作者表示经历信息过载。同时，研究者在文献检索和阅读过程中花费大量时间：现有工具如 Semantic Scholar 通过语义搜索缩短了文献评估时间，而 Elicit AI 利用语言模型自动搜索和摘要论文。然而，它们主要提供检索和可视化服务，缺乏从抓取、解析、知识抽取到问答、学习管理的闭环体验。本项目旨在结合向量数据库与大型语言模型，在高校及科研机构推广一站式的论文知识管理平台。

## 2.2 问题说明

当前科研人员面临以下问题：

- 文献增长过快：每年发表的论文数量持续增长，手动检索和筛选效率低。
- 内容理解成本高：传统检索工具仅提供标题和摘要，缺乏结构化的概念、方法和实验信息。
- 知识碎片化：用户难以建立概念之间的关联，研究脉络难以追溯。
- 缺乏主动推送：现有平台主要基于检索，缺少基于兴趣的订阅与推荐。
- 学习管理不足：读者难以同步收藏、笔记与阅读历史，无法对比或复习已读文献。

## 2.3 产品定位说明

产品将作为一款面向科研人员的免费、非商业性 Web 应用，提供从论文采集到知识问答的完整解决方案。核心定位如下：

- 面向对象：研究人员、研究生、图书馆员以及对学术前沿感兴趣的公众。
- 核心价值：通过自动化抓取与结构化解析，构建可检索、可关联、可交互的论文知识库，提高文献搜集和理解效率，并利用 LLM 支持基于知识库的问答和个性化推荐。
- 差异化优势：与现有的语义检索或可视化工具相比，系统以 arXiv 为基础进行全链路信息管理，实现文献抓取、知识抽取、概念关联、智能问答和学习管理的闭环，不仅提供检索，还支持深入阅读和研究脉络分析。

## 3.2 备选方案和竞争

市场上已有一些学术搜索和知识管理工具，可作为对比：

### 3.2.1 Semantic Scholar

Semantic Scholar 是 AI 驱动的学术搜索引擎，使用高级自然语言处理技术理解查询语义，以概念、同义词和引用网络来排序结果，帮助研究者发现传统关键字搜索可能遗漏的论文。它提供 TLDR 摘要和引文分析，但主要定位于检索与阅读，而非全流程知识管理。

### 3.2.2 Research Rabbit

Research Rabbit 是一款免费工具，提供语义搜索和引文网络可视化，通过先进的自然语言处理模型分析查询概念，检索语义相似的论文，并以交互式网络图展示论文之间的引用、合作和语义关系。其可视化功能帮助用户直观理解研究领域，但缺乏自动抽取论文内容和问答功能。

### 3.2.3 Elicit AI

Elicit AI 是由 Ought 开发的研究助理，使用大型语言模型自动执行文献搜索、摘要和数据提取。它能提取论文中的关键结论和数据，支持系统化文献回顾，但侧重于信息提取与表格整理，缺乏知识图谱和学习管理功能。

### 3.2.4 Connected Papers

Connected Papers 利用共被引和文献耦合的相似度度量，通过可视化图谱帮助研究者发现相关论文。用户可以以种子论文或关键词为起点，过滤年份、关键字和开放访问条件，并生成力导图展示论文相似度。优点是直观呈现文献关系，限制在于免费版图谱数量有限且对偏冷门领域覆盖不足。

# 4. 产品概述

该系统旨在搭建一个面向研究人员的论文知识平台，其上下文环境如下：

- 外部系统：arXiv API 提供论文元数据和 PDF 下载；LLM 问答服务提供自然语言生成能力；浏览器为唯一客户端。
- 内部组成：后端使用 FastAPI 框架，负责抓取任务调度、数据存储和接口服务；元数据存储于 PostgreSQL；向量数据库用于存储文本嵌入以支持语义检索；概念/引用关系库保存知识图谱；前端基于现代 Web 技术，提供论文列表、详情、搜索、问答与学习管理界面。
- 典型流程：系统定期调用 arXiv API，依据学科和关键词抓取新论文，并通过分页机制限制请求负载；下载 PDF 后解析其结构化内容并生成各类 Markdown 文档；抽取核心概念、方法和实验结论，构建概念关系图；将论文嵌入向量库以支持相似度检索；用户通过 Web 界面检索或查看知识 Wiki，并可向 LLM 问答服务发起问题，服务基于知识库返回答案及来源定位。

# 5. 产品特性

## 5.1 论文自动抓取与管理

- 定时抓取：支持设定任务，定时从 arXiv 按学科或关键词拉取论文，并通过 `search_query`、`start` 和 `max_results` 参数分页。
- 分类入库与去重：利用作者、主题、发表日期等元数据，将新抓取论文按类别入库，并对已存在记录进行去重。
- 元数据展示：存储并展示标题、作者、摘要、类别、发布日期和链接等信息，这些信息来自 arXiv API 返回的 `<title>`、`<author>`、`<summary>`、`<category>`、`<published>` 等字段。

## 5.2 论文结构化解析与知识抽取

- 格式解析：解析论文 PDF 或 HTML，生成 [`summary.md`](http://summary.md)（摘要）、[`concept.md`](http://concept.md)（概念）、[`methods.md`](http://methods.md)（方法）等 Markdown 文档。
- 知识抽取：利用自然语言处理技术抽取核心概念、研究问题、方法描述、实验结论和贡献，构建概念之间的关联关系并存储至概念/引用关系库。
- 版本管理：支持对论文多版本内容的更新与差异比较，确保抽取数据的时效性。

## 5.3 论文 Wiki 与检索

- 知识 Wiki：为每篇论文生成包含摘要、概念、方法、实验和引用关系的知识页面，并支持双向链接。
- 多维检索：支持按标题、作者、关键词、研究方向、概念标签等方式检索；支持语义检索，利用向量数据库实现相似度搜索。
- 关系可视化：展示论文之间的引用关系、主题关联和概念关联，帮助用户理解研究脉络。

## 5.4 智能问答

- 自然语言提问：用户可以基于论文内容、概念解释、研究方法和演化脉络提出问题。
- 知识库驱动：系统从向量数据库和概念关系库检索相关文档并组织答案，再由 LLM 生成自然语言回复，同时返回论文出处或相关段落定位。
- 对话记录：保存问答历史，方便用户回顾。

## 5.5 学习管理

- 收藏与笔记：用户可以收藏论文、撰写笔记、标注观点，并支持对比阅读不同论文。
- 阅读历史：记录用户的阅读时间、频次和关注主题，并在个人主页呈现。
- 社区互动：提供评论功能，便于用户分享心得。

## 5.6 进阶功能

- 研究脉络分析：针对某一研究主题自动生成发展脉络图和代表性论文列表，分析研究趋势。
- 个性化推荐与订阅：用户可按照研究主题订阅每日推送的新论文摘要；系统根据用户阅读历史进行相关论文推荐。

# 6. 约束

- 非商业性质与 arXiv API 合规：项目属于独立的非商业开源项目，应遵循 arXiv API 的使用条款，不得使用 “arXiv” 名称或标识进行品牌推广，并需在产品中注明“感谢 arXiv 提供开放获取互操作性”。
- 客户端要求：前端必须兼容主流浏览器及不同分辨率/尺寸，适用于 PC 和移动端。
- 数据量限制：初期支持不少于 100 条论文元数据，并在 100 并发场景下保证检索、问答和学习管理的响应时间小于 3 秒（不包括 LLM 响应时间）。
- 准确率要求：论文解析、检索和问答的准确率需达到 90% 以上；需要通过持续迭代优化模型和算法。
- 安全性与隐私：禁止在系统中存储敏感个人信息；笔记和评论等用户数据应加密存储和权限控制。
- 技术栈约束：后端采用 Python 3.x、FastAPI 框架，数据库使用 PostgreSQL 与向量库，算法库需支持中文处理；LLM 可通过云服务或本地部署调用，需考虑成本和稳定性。

# 7. 质量属性

- 易用性：界面友好，支持多语言（初期为中文），通过简洁的导航、搜索和过滤功能帮助用户快速找到信息。提供新手引导和在线帮助。
- 可靠性：系统应稳定运行，遇到网络或 API 故障时提供重试与异常提示，保证数据完整性与一致性。
- 性能：按照约束中所述的性能指标优化后台服务、数据库查询及向量检索，采用缓存和异步任务降低响应时间。
- 安全性：采用 HTTPS 加密通信，用户认证与授权机制，限制管理员与普通用户的不同权限，防止未授权访问。
- 可维护性与扩展性：模块化设计，前后端分离，易于在未来增加新的数据源或算法模型。使用自动化测试保障代码质量。
- 兼容性：遵循现代 Web 标准，确保在 Chrome、Firefox、Edge 等浏览器正常运行，并适配不同屏幕尺寸。

# 8. 优先级

根据项目 MVP 的目标，功能优先级如下：

| 优先级 | 功能 | 说明 |
| --- | --- | --- |
| 高 | 论文自动抓取与管理 | 构成系统基础，用于数据来源。 |
| 高 | 论文结构化解析与知识抽取 | 保证知识库内容质量，是问答和检索的前提。 |
| 高 | 论文 Wiki 与检索 | 面向用户的核心功能，提供结构化展示和搜索。 |
| 高 | 智能问答 | 提升用户交互体验，通过 LLM 实现对知识的深入理解。 |
| 中 | 学习管理 | 支持收藏、笔记等个人功能，提升平台粘性。 |
| 中 | 研究脉络分析 | 在核心功能稳定后实现，为用户提供宏观视角。 |

# 9. 其他产品需求

## 9.1 适用的标准

- 遵循 Web 内容无障碍指南（WCAG）以保障可访问性。
- 数据和服务遵循行业标准协议如 HTTP/HTTPS、RESTful API。
- 遵循《中华人民共和国著作权法》等相关法律法规及开源许可证规定。

## 9.2 系统需求

- 服务器需要支持部署 Python 3.x 环境，并安装 FastAPI、PostgreSQL、向量数据库（如 pgvector）及相关 NLP 模型。
- 推荐配置：8 核 CPU、16 GB 内存、100 GB 磁盘；如需本地推理 LLM，应配置 GPU。
- 用户端仅需现代浏览器，无需安装额外插件。

## 9.3 环境需求

- 生产环境应具备稳定的网络连接，以确保抓取任务和问答服务的可用性。
- 开发和测试环境应模拟多用户并发场景，验证性能指标。

# 10. 文档需求

## 10.1 用户手册

应编写用户手册，介绍系统功能、界面操作、搜索技巧、问答示例、收藏与笔记管理方法，并提供常见问题解答。建议以在线文档和 PDF 两种形式发布。

## 10.2 联机帮助

在系统内集成联机帮助，支持关键页面的提示和引导。联机帮助应包含搜索栏、目录和关键字索引，支持跳转到相关用户手册章节。

## 10.3 安装指南、配置文件、自述文件

项目应提供详尽的安装指南，说明依赖项安装、数据库初始化、配置文件说明和部署步骤；自述文件应描述版本特性、已知问题和更新日志，以便开发者和部署人员快速上手。
