系统架构全景图
关键算法清单
检索

RRF — Reciprocal Rank Fusion

融合向量相似度排序（pgvector cosine）与全文搜索排序（ts_rank）的结果。每个文档在各自列表中倒数排名取平均，避免归一化问题，比线性加权更鲁棒。

Top-K₁ (vector)+ Top-K₂ (FTS)→ RRF 评分→ Top-K 最终
图谱

Concept Graph BFS 扩展

从用户查询中提取概念实体，在 concept_relations 表中 BFS 1-2 跳扩展关联概念，用扩展概念集过滤 paper_concepts 缩小候选范围，再进入向量检索。

NER 抽取实体→ BFS 1-2跳→ 候选论文集→ 向量检索
NLP

Semantic Chunking（语义分块）

不是固定 token 数切分，而是基于段落/章节边界 + embedding 相似度断点检测，在语义自然边界处分割，保证每个 chunk 内容完整、上下文自包含。

段落分割→ 相邻段落相似度→ 低相似度处断开→ 500±100 tokens
NLP

LLM 驱动概念关系抽取

用 Few-shot Prompt 驱动 LLM 从论文中抽取 (实体, 关系, 实体) 三元组，建立概念间的 IS_A、USES、IMPROVES、RELATED_TO 等关系类型，构建轻量知识图谱。

论文全文→ Few-shot Prompt→ 三元组列表→ concept_relations
检索

PostgreSQL Full-Text Search

对标题、摘要、作者建立 tsvector 列 + GIN 索引，支持中文分词（zhparser/jieba）和英文，使用 ts_rank 按 TF-IDF 加权排序，支持短语搜索和前缀匹配。

to_tsvector(title,abstract)→ plainto_tsquery(keyword)→ ts_rank 排序
向量

HNSW 近似最近邻搜索

pgvector 的 HNSW 索引实现近似最近邻检索，构建多层可导航小世界图，查询时从顶层开始贪心搜索，O(log N) 复杂度，比 IVFFlat 精度更高。

Query Embedding→ HNSW 图遍历→ Top-K 近似解
排序

PageRank 论文影响力评估

在 paper_citations 引用图上运行 PageRank，迭代计算每篇论文的影响力得分，用于"代表性论文"排序和趋势分析中的里程碑论文识别。

引用图邻接矩阵→ 阻尼 d=0.85 迭代→ PR 值收敛→ 排序
去重

SimHash + 标题模糊匹配

论文去重采用两级策略：先 arxiv_id 精确匹配，再对标题做 SimHash 指纹 + 海明距离 < 3 判定为重复，兼顾精度和召回，避免仅靠 ID 遗漏同一论文的多版本。

arxiv_id 精确→ SimHash 指纹→ Hamming < 3→ 判重
推荐

Content-Based + 协同过滤混合推荐

内容侧：基于用户收藏论文的概念向量做余弦相似度推荐；协同侧：基于用户-论文交互矩阵做矩阵分解（SVD），融合两者分数做加权推荐。

概念向量余弦+ SVD 矩阵分解→ 加权融合→ Top-N 推荐
趋势

时间序列趋势检测

按月聚合论文发表量 + 概念提及频率，用滑动窗口平滑 + 一阶差分检测拐点，识别"新兴热点"和"成熟衰退"阶段，自动标注里程碑论文。

月聚合时序→ 滑动均值平滑→ 差分拐点检测→ 趋势标注
解析

PDF Layout 检测与章节识别

基于 PyMuPDF 的块级文本提取 + 字体大小/粗体/位置启发式规则，识别论文标题、作者、摘要、章节标题层级，过滤页眉页脚和参考文献。

PyMuPDF 块提取→ 字体/位置规则→ 章节树构建→ 结构化输出
NLP

Two-Stage Prompt 结构化摘要生成

Stage1: Map 阶段并行对每个 chunk 生成局部摘要；Stage2: Reduce 阶段汇总局部摘要 + 原文元数据，生成 summary / methods / concepts / experiments 四个 markdown 文件。

Map: 逐 chunk 摘要→ Reduce: 汇总合并→ {summary,methods,concepts}.md
向量

Embedding 批量生成与缓存

论文入库后异步调用 text-embedding-3-small（1536维）批量生成 chunk embedding，写入 paper_chunks.embedding 列。已生成的不重复调用，增量更新。

新 chunk 入队→ 批量 API 调用→ pgvector INSERT→ HNSW reindex
检索

SQL-First Fallback 检索策略

所有查询统一先走 SQL 结构化检索（对 papers / concepts / methods / summaries / authors 等多表联合查询），利用已抽取的结构化数据。若结果数 ≥ 3，直接用结构化摘要作为上下文喂给 LLM；若不足，再 Fallback 到 Hybrid Search（pgvector + FTS + RRF），避免不必要的 embedding 调用和向量计算。

任意查询→ SQL 多表联查→ count≥3?→ YES: 结构化上下文/ NO: Hybrid Search
