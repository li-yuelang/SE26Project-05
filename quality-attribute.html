arxiv-PaperMate 可靠性质量属性架构视图

本系统是一个 AI 驱动的 arXiv 论文助手，涵盖论文自动抓取、PDF 解析、语义分块、 向量化索引、结构化分析与 RAG 智能问答。外部依赖多、处理链路长，因此可靠性是最核心的质量属性。

核心质量属性：可靠性 (Reliability)
🎯 为什么可靠性最重要？

长链路依赖

论文分析管线涉及 arXiv API、PDF 下载、解析器、LLM、嵌入模型、数据库等多重外部依赖，任一步骤失败都会中断整个流程。

异步任务脆弱性

论文分析与抓取通过 Celery 异步执行，worker 崩溃、网络抖动、API 限流都可能导致任务静默失败，用户无法感知。

用户信任关键

研究人员依赖系统获取准确的论文分析和可靠的问答结果。若分析结果丢失或不一致，将严重损害用户对系统的信任。

🛡️ 可靠性设计战术详解
战术类别具体措施代码/配置位置作用
故障预防 PDF 下载前校验：Content-Type 检测 + PDF 魔数 (%PDF) 校验 + 大小上限 50MB paper_analysis.py :: download_pdf() 提前拒绝非法输入，避免无效处理占用资源
故障预防 Embedding 批次完整性校验：维度 (1536d) 与数量双重检查 paper_analysis.py L146-148 防止部分嵌入失败导致数据不一致
故障预防 arXiv API 请求间隔 3 秒 + Redis 分布式锁 (120s TTL) config.py L47-49 遵守 API 速率限制，避免被 ban
故障预防 临时文件隔离：NamedTemporaryFile + delete=True 确保异常自动清理 paper_analysis.py :: _materialise_pdf() 避免磁盘残留文件积累
优雅降级 向量检索不可用 → 回退到关键词 (ILIKE) 检索 rag.py :: retrieve() L99-101 Embedding API 故障时仍可检索
优雅降级 LLM 不可用 → 回退到抽取式答案 (fallback_answer) rag.py :: answer() L176-179 LLM 服务故障时仍可返回相关片段
优雅降级 无 API Key 时直接使用关键词检索 + 抽取式回答 rag.py L87, L171 零配置最小可用模式
故障恢复 论文分析 max_retries=3，Celery 自动重试 config.py L39 瞬时故障（网络抖动）自动恢复
故障恢复 arXiv 请求 max_retries=3 + 结构化错误记录 config.py L48 抓取失败自动重试
故障恢复 分析失败状态持久化：mark_analysis_failed 记录错误信息到 DB analysis_state.py + paper_analysis.py L178 失败任务可追溯，支持 force=true 重新执行
守卫检查 分析状态机：每阶段 set_analysis_state + commit，精确追踪进度 paper_analysis.py L107-169 任一阶段失败都能定位，支持断点恢复
守卫检查 幂等设计：parsed_status=="completed" && !force 时跳过已处理论文 paper_analysis.py L104 重复请求不产生副作用
守卫检查 超时控制全覆盖：LLM 90s / Embedding 60s / PDF 45s / arXiv 60s config.py L23-47 防止外部服务 hung 住导致资源泄漏
守卫检查 结构化日志 + 统一错误码响应 logging.py + exceptions.py 生产问题快速定位与排查
🚀 部署可靠性视图

容器化部署

  • Docker Compose 一键编排所有服务
  • PostgreSQL + Redis 独立容器，资源隔离
  • 健康检查端点 GET /health 支持监控探活

CI/CD 保障

  • GitHub Actions 自动运行后端测试
  • 代码合并前必须通过单元测试
  • Alembic 数据库迁移自动验证

SSH 隧道安全连接

  • 本地开发通过 SSH 端口转发连接云端 DB/Redis
  • 避免数据库端口直接暴露公网

一键启动脚本

  • Windows / macOS / Linux 三平台启动脚本
  • 自动打开 5 个终端窗口并行启动所有服务
  • 减少手工操作导致的配置错误
📋 总结

arxiv-PaperMate 论文助手系统的核心质量属性是可靠性。 系统通过分层架构（接入层 → 应用层 → 任务队列层 → 处理管线层 → 数据层）， 结合四大类可靠性战术——故障预防（输入校验、限流）、优雅降级（检索/LLM 多级回退）、 故障恢复（自动重试、状态持久化）、守卫检查（状态机追踪、超时控制、幂等设计）—— 确保在外部依赖故障、网络异常、数据处理错误等场景下，系统依然能提供稳定可靠的服务。
